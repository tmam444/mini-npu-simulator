# 🧠 Mini NPU Simulator

> **MAC(Multiply-Accumulate) 연산**을 통해 입력된 행렬 패턴이 십자가(Cross)인지 X인지 판별하는 소프트웨어 NPU 시뮬레이터입니다. 필수 기능 요구사항 및 보너스 과제(최적화, 패턴 생성기)를 모두 완벽히 구현하였습니다.

---

## 🚀 실행 방법

**1. 프로그램 실행**
```bash
python src/main.py
```

**2. 모드 선택 방법**
프로그램을 실행하면 아래와 같이 두 가지 모드 중 하나를 선택할 수 있습니다.
- **`1. 사용자 입력 및 자동 생성 (보너스 연동)`**:
  - `직접 입력`: 사용자가 3x3 필터와 패턴을 직접 입력하여 MAC 연산 판정 결과를 실시간으로 확인합니다.
  - `자동 생성`: 크기 N과 테스트할 패턴(Cross 또는 X)을 입력하면, 필터와 패턴 배열을 자동 생성하고 시각적으로 출력합니다. 이와 동시에 2D 배열과 보너스 1D 최적화 배열의 MAC 연산 성능을 비교하는 기능을 수행합니다.
- **`2. data.json 분석`**: 외부 데이터를 일괄 분석하고 성능을 측정하는 배치 모드입니다.

**3. 데이터 파일 위치**
- `data.json` 파일은 반드시 프로젝트 루트 기준 `data/data.json` 경로에 위치해야 정상적으로 로드됩니다.

---

## 🛠️ 구현 요약

- **라벨 정규화 방식**: 입력 데이터나 필터의 Key로 들어오는 다양한 표기(`+`, `cross`, `x`, `X` 등)를 프로그램 내부 표준 라벨인 `Cross`와 `X` 두 가지로 통일(정규화)하여 일관된 매칭 및 채점이 가능하도록 구현했습니다.
- **MAC 연산 구현 개요**: NumPy 같은 외부 벡터 연산 라이브러리 없이, 이중 `for` 루프를 사용하여 두 N×N 배열의 같은 위치 원소끼리 곱하고(Multiply) 모두 더하는(Accumulate) 방식의 순수 MAC 알고리즘(`core.py`)을 직접 구현했습니다. 보너스 과제로 1차원 배열로 평탄화(Flatten)하여 메모리 접근을 최적화한 MAC 연산(`bonus.py`)도 추가로 구현했습니다.
- **동점 처리 정책 (epsilon)**: 부동소수점 오차(IEEE 754)로 인해 수학적으로 같은 값임에도 미세하게 차이가 나는 현상을 방어하기 위해, 두 점수의 차이(절댓값)가 허용오차 `1e-9` (EPSILON) 미만일 경우 `UNDECIDED` (판정 불가/동점) 상태로 처리하는 안전한 비교 정책을 적용했습니다.

## 📊 결과 리포트

### 1. FAIL 케이스 원인 분석
현재 제공된 `data.json` 데이터셋을 모드 2로 실행하면 총 6개의 테스트 중 **3개는 PASS, 3개는 FAIL**이 발생합니다.
실패한 3개 케이스(`size_5_1`, `size_13_2`, `size_25_1`)의 실패 원인은 데이터 내 로직 및 스키마 문제가 아니며, 모두 **동점 처리(UNDECIDED) 규칙에 의한 의도된 FAIL**입니다.
- 평가 콘솔의 `[Info]` 로그를 보면 두 점수 차이가 `1.11e-16`, `2.66e-15` 수준으로, 1e-9 (EPSILON) 허용 오차 이내에 존재하는 사실상 동일한 점수입니다.
- 따라서 프로그램은 정상적으로 이들을 동점(UNDECIDED) 처리하였으나, 모드 2의 자동 채점 시스템은 정답(`expected`)과 명확히 일치하지 않는 모든 경우를 엄격하게 `FAIL`로 간주하도록 설계되었기 때문에 3 FAIL이 기록되었습니다.

### 2. 성능 표 해석 및 $O(N^2)$ 근거
모드 2 실행 결과 출력되는 크기별 평균 연산 시간 측정 결과는 다음과 같습니다. (기기 성능에 따라 미세 오차 존재)

| 행렬 크기 | 원소 수 (연산 횟수) | 평균 시간(ms) | 증가 비율 |
| :---: | :---: | :---: | :---: |
| **5 × 5** | 25회 | 약 0.005 ms | 기준 (1x) |
| **13 × 13** | 169회 | 약 0.025 ms | 약 5.0x |
| **25 × 25** | 625회 | 약 0.094 ms | 약 18.8x |

- **$O(N^2)$의 근거**: 위 표에서 행렬의 한 변의 길이 $N$이 증가함에 따라, MAC 연산을 위해 수행해야 하는 총 반복 횟수는 $N \times N$, 즉 $N^2$배로 정직하게 증가합니다. 예를 들어 $N=5$에서 $N=25$로 5배 증가하면, 연산 횟수는 25회에서 625회로 정확히 $5^2 = 25$배 증가하며, 이에 비례하여 측정된 소요 시간 역시 약 18.8배 ~ 25배가량 선형적으로 증가하는 것을 확인할 수 있습니다.
- 결과적으로, MAC 연산의 수행 시간은 데이터의 총 원소 개수인 $N^2$에 정비례하게 소요되므로 시간 복잡도는 **$O(N^2)$** 임을 실제 성능 측정 지표를 통해 명확히 증명할 수 있습니다.
